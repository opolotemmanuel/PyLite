# Repository layout

The project uses a conventional Python package layout. Existing source and
command paths are preserved.

```text
pylite/
├── README.md                 Project entry point and command summary
├── pyproject.toml            Package metadata and installed CLI definition
├── pylite.ps1                Optional Windows launcher
├── .gitignore                Local/generated files excluded from Git
├── .github/workflows/        CI configuration
├── pylite/                   Importable language implementation
├── docs/                     Guides, reference, and verification records
│   ├── README.md             Documentation index
│   ├── getting-started.md    Setup and execution
│   ├── language.md           Current language reference
│   ├── development.md        Implementation and validation workflow
│   ├── repository-layout.md  This folder map
│   └── verification.md       Historical and current validation results
├── examples/                 Runnable .lite programs and example index
└── tests/                    Automated tests, installed smoke check, and test guide
```

The outer `pylite/` is the project folder; the inner `pylite/` is the Python
package. Run `python -m pylite` from the project root or after installation.
The CLI entry file is `pylite/__main__.py`.

| File type | Location |
| --- | --- |
| Language implementation | `pylite/` |
| Runnable language demonstrations | `examples/` |
| Test cases and installation checks | `tests/` |
| User guides, reference, and reports | `docs/` |
| Package configuration, overview, and launcher | Project root |
| Hosted automation | `.github/workflows/` |

## Generated and environment-managed folders

`build/` and `pylite_language.egg-info/` are generated by packaging, not additional
source implementations. Packaging may regenerate them in these conventional
locations. Python may create `__pycache__/` folders next to imported files.
Virtual environments normally belong in the ignored `.venv/` directory; package
outputs may use the ignored `dist/` directory. These are not documentation folders.

Hidden folders such as `.git`, `.agents`, `.codex`, and `.aws` may contain Git or
environment-managed state. They are left in place. The original source folder had empty Git metadata during verification. The
canonical destination now has its own preserved Git history; see
[the migration report](migration.md).

No existing source, tests, examples, or generated artifacts were relocated in the
organization pass. Their current locations already fit this structure.


`lexer_core.py` at the root is a preserved historical scanner skeleton, with
separate `#[ ... ]#` comment assumptions. It is not the installed language lexer
and is not imported by `pylite/`. Test the language through `python -m pylite`;
its lexer is `pylite/lexer.py`, implementing nested `#| ... |#` comments.
